# Style Router

先确定发布场景、覆盖范围和每张图要产生的认知变化，再选择视觉语言。Style 是表达机制，不是题材皮肤。配图中的事实性文字和关系必须先写入 `article-draft`；Style 只能决定表达，不能补充事实。

## 优先级

1. 用户明确指定任一受支持 Style：直接采用，不自动改写；其他 Style 按 `SKILL.md` 的支持范围处理，不生成临时 Profile。
2. 用户未指定：按核心意义由场景动作还是结构关系承载来自动选择，并在 `figure-spec` 开头说明理由。
3. 同一套图默认只用一种 Style；只有用户明确要求混用时才逐图路由。

## 自动选择

| 判断信号 | Hand-Drawn Cartoon Infographic | Halftone Paper Collage |
| --- | --- | --- |
| 内部表达类型 | 场景驱动解释 | 结构驱动编辑 |
| 核心意义载体 | 角色、对象、动作、处境或类比 | 边界、层次、裁切、并置、转化或空间关系 |
| 读者如何理解 | 看见谁在什么情境中做了什么 | 看见什么属于、改变、分离、对照或被选择 |
| 典型任务 | 行动指导、人物处境、入门解释、简单因果 | 系统解释、采用判断、比较、边界、状态变化 |
| 失败风险 | 退化为图标网格、卡通装饰或泛化人物 | 退化为半调背景、泛复古拼贴或重复卡片模板 |

不要仅按“技术内容 / 非技术内容”或“步骤 / 比较”等信息关系分类；相同关系可以由不同机制承载。依次判断：

1. 移除角色、动作或主场景后，核心解释明显失效：选择 `Hand-Drawn Cartoon Infographic`。
2. 移除边界、层次、裁切或空间操作后，核心关系明显失效：选择 `Halftone Paper Collage`。
3. 两者都成立时，选择所需语义角色更少的一种。
4. 仍然相同：行动指导或人物处境选择手绘；系统解释、采用判断、比较或边界选择拼贴。

## 覆盖范围

- 社交媒体、公众号多图轮播或推广套图：选择性提炼 4–6 个最值得视觉化的信息点；允许合并章节。
- 教程、报告、系统解释或用户要求完整覆盖：主要章节均须至少映射到一张图；可以增加图数。
- 无法判断发布场景时：按社交媒体多图轮播处理，并明确这是默认假设。

先在内部建立 Card Responsibility Brief，不输出为独立文件：

- 本图唯一认知目标；
- 核心主张；
- 信息关系；
- 必须出现的文字；
- 来源原生视觉锚点；
- 事实与证据边界；
- 空白区域的责任。

## 画幅

优先级：用户指定 > 发布平台要求 > Folio 默认。画幅与 Style 解耦。

- 没有用户或平台要求时，两种 Style 均默认 `3:4` 竖版，建议画布 `1536×2048 px`。
- 同一套图统一比例与建议画布；每张图仍需重复写明比例、方向和像素值。
- 用户或平台指定其他比例时，建议画布的宽高比必须与目标比例严格相等。不得把工具的常见默认尺寸当作近似值，例如 3:4 不能写成 `1024×1536 px`，因为后者是 2:3。
- 若下游工具提供 Aspect Ratio、Canvas Size 或 Width/Height 设置，要求用户显式设置目标值且不使用 Auto；只有 prompt 输入时，保留完整画布约束，同时明确这只能提高遵循率，不能覆盖工具固定比例。

自动路由理由必须写成“核心意义由 `[场景动作 / 结构关系]` 承载；若移除 `[关键机制]`，读者将无法理解 `[认知变化]`，因此选择 `[Style]`”。不能只写“更适合技术内容”“信息关系是比较”或“更有设计感”。
