# Figure Spec 生图前 QA

只检查规格，不生成图片，也不替代 Bitmap 后验 QA。先逐图检查，再检查整套；任一硬失败都必须修正后重检。

## 严重级别

- `FAIL`：事实越界、缺少 Style/画幅/建议画布/下游执行要求/语言/必需文字/统一视觉系统、比例与像素冲突、单图未完整继承视觉系统、依赖全局上下文、文字不可读风险、虚假证据或错误视觉关系。
- `WARN`：信息偏密、层级弱、构图重复、留白职责不清或 Style 机制不足。
- `PASS`：约束完整且可直接生图。

最终 `PASS` 是硬门槛：必须为零个 `FAIL`，且每个 `WARN` 都已经修正或以可核查证据说明不构成风险。不能用“整体可用”覆盖单图失败。

## 可重复执行的硬门槛

先把每个 `## 图 N` 到下一张图之前的内容视为一张独立任务包，不继承文件开头或其他图片的信息。逐包执行：

| 门槛 | 通过条件 | 失败证据 |
| --- | --- | --- |
| 固定结构 | 同时存在「参考图片内容」和「配图规格」 | 任一小节缺失 |
| 必需字段 | Style、画幅、建议画布、下游执行要求、语言、认知目标、核心主张、信息关系、构图机制、视觉锚点、色材、文字安全区、禁区事实边界、完整生图指令均有实际值 | 字段缺失、为空，或仍含方括号占位符 |
| 实际文字 | 主标题及所有需要出现的正文、强调词、限制均逐项写明；没有则明确写“无” | “见上文”“同上”“略”等上下文引用 |
| 画布数学一致性 | 建议画布的宽:高与目标比例严格相等；3:4 默认值为 1536×2048 px | 3:4 搭配 1024×1536 px，或任何近似、冲突比例 |
| 自包含 Prompt | 完整生图指令以最高优先级画布约束开头、以原生画布收束句结尾，并用输出语言自然描述 Style、语言、核心视觉机制、文字避让与事实禁区 | 缺少首尾画布约束、把规范英文 Style 名称当作 Prompt 风格前缀、照搬内部 Profile 名称/版本号、只写“按上述生成”或依赖文件级声明 |
| 下游执行 | 要求支持比例或尺寸参数的工具显式设置目标值且不使用 Auto；对 prompt-only 工具不做超能力承诺 | 只依赖 prompt、允许 Auto，或声称可以覆盖工具固定比例 |
| 路由依据 | 自动路由理由说明所选媒介的表达优势、关键视觉机制与另一种 Style 所需的额外转换 | 只写人物有无、题材、信息关系、技术内容或“更有设计感” |
| 来源身份事实 | 有明确命名来源时，规范名称、实体类型与“开源”等描述均能回溯到文章和来源；证据不足时缩窄为中性描述 | 从 GitHub URL、章节编号或视觉印象推断“开源书”“论文”“产品”等身份 |
| 来源身份分布 | 首图建立名称、实体类型与主题；每张内页在「必要署名 / 限制」中保留“规范名称 · 实体类型”；实体类型必须有来源支持；整套至少使用两种身份表达方式 | 只有首图可识别来源、只重复同一页脚，或身份信息取代本图主张 |
| 背景选择 | 文件头给出具体背景及用户、来源、平台、内容语气或文字对比依据；背景选择前内部比较至少三个色温或明度不同的候选 | 只因“手绘/拼贴”使用暖米白、奶油色、羊皮纸或复古纸，或没有可说明的选择依据 |
| 视觉系统继承 | 文件头给出具体统一视觉系统；每张「色彩、材质与氛围」及完整 Prompt 逐项完整重复其背景、选择依据、颜色角色、材质、笔触、光影、字体性格与适用的连续性约束；允许自然语序不同，不允许值缺失或改义 | 使用“同上/沿用”、遗漏固定值、换背景色族、交换颜色语义、引入新媒介或新光影 |
| 套图一致性 | 每张 Style、画幅、建议画布和统一视觉系统与全套声明相同；未指定画幅时两种 Style 均为 3:4 竖版 | 混用 Style、出现冲突像素或视觉固定值，或因 Style 改变默认画幅 |
| Style 专项 | 有明确命名来源时先有至少 1 个来源身份锚点；手绘图另有明确内容载体、手绘解释机制和至少 2 个内容解释锚点，人物可有可无；半调图另有主导编辑操作、关系、至少 2 个内容解释锚点、文字—物体联动与 removal delta | 只有名称、风格形容词、纹理说明、泛化人物或泛化图标 |

人工语义检查不能被字段检索替代。字段检索只能证明结构存在，事实边界、文字负载、编辑操作是否真正承载关系仍需逐图判断。

## 逐图检查

1. **事实边界**：核心主张、数字、公式、名称、命令、URL、限制，以及分类、步骤、按钮、卡片和示意物的全部可读标签，均能追溯到 `article-draft`；「参考图片内容」是唯一可读文字白名单，没有新增效果、排名、关系、证据或为构图补造的示例。白名单外的代码、命令、UI、ID、编号和状态文案必须留白、不可读或删除，否则标记 `FAIL`。
2. **参考图片内容**：主标题、正文、强调词与必要限制完整明确；没有用“同上”或省略号代替实际内容。
3. **自包含性**：单独复制该图时，仍有规范 Style 名称、画幅、建议画布、下游执行要求、方向、语言、文字、认知目标、关系、构图、锚点、色材、禁区、安全区和完整生图指令；规范英文 Style 名称只出现在 Style 字段，不得作为完整生图指令中的风格前缀；内部 Profile 名称与版本号不得进入产物。
4. **来源身份**：有明确命名来源时，「必要署名 / 限制」与完整生图指令逐字包含“规范名称 · 实体类型”这一最小来源标识，实体类型必须有来源支持；视觉锚点明确区分至少 1 个来源身份锚点与至少 2 个内容解释锚点。文章的来源、核查日期和不确定性尾注不得自动充当图上署名。执行 Recognition Test：脱离账号与发布上下文，仍能判断它是什么、叫什么、讲什么。执行 Generic Substitution Test：把来源替换为实体类型或主题不同的命名来源，并只更新名称与最小来源标识；若其余身份机制和内容解释锚点仍无需改变，标记 `FAIL`。仅替换为同类型、同主题来源不构成失败，也不得为通过测试补造来源未提供的独有 Logo、资产或视觉特征。无明确来源时来源身份锚点写“无明确来源”，不得补造。
5. **文字负载**：主张 5 秒内可扫读；正文可在目标画幅中留出合理字号与行距。无法排下时先压缩文案或拆图。
6. **层级与安全区**：标题、主体、辅助说明有明确顺序；来源标识保持次级；文字不贴边，不被人物、图标、裁切线、纸边、连接线、阴影或边框覆盖。
7. **比例**：画幅和建议画布与全套声明一致，宽高数学上严格等比；完整指令首尾重复同一目标。3:4 不得搭配 1024×1536 px；如逐图不一致，必须有用户明确要求。
8. **统一视觉系统**：文件头的背景必须有用户、可核查来源视觉、平台环境、内容语气或文字对比依据；“手绘”“拼贴”“更有质感”不构成依据。未有明确依据却机械使用暖米白、奶油色、羊皮纸、泛黄纸或复古纸，标记 `FAIL`。「色彩、材质与氛围」先逐项完整继承文件头全部固定值及背景选择依据，再单列本图变化；完整生图指令重复同一组固定值。允许为自然语序改变字段连接方式，但逐项核对后不得有值缺失或改义。参考色可作为跨工具锚点，但不得承诺像素一致。本图可改变构图重心、既有强调色使用比例，以及 Hand-Drawn 的对象/注释/动作或状态/空间组织，或 Halftone 的主导编辑操作；不得引入新背景色族、交换颜色语义、改变材质/笔触/光影/字体性格，或让重复对象、人物、纸张、网点体系漂移。
9. **Style 参与表达**：
   - 手绘：声明对象演示、注释图、流程、空间关系、对照或必要场景中的至少一种内容载体，并使用至少 2 个内容解释锚点；移除对象关系、注释、状态变化、动作或空间组织后理解应明显受损。人物可有可无；只加入泛化讲解员、工程师或产品经理而无内容职责，标记 `FAIL`。
   - 半调拼贴：声明可观察的编辑操作、对应信息关系、至少 2 个内容解释锚点、文字—物体联动与 removal delta；移除边界、层次、裁切或空间操作后理解应明显受损，不是身份标识或纹理背景。
10. **视觉锚点**：两类锚点具体、可执行并能共同回答来源身份与本图主张；泛化科技符号、GitHub Logo、书本或项目名称都不能单独承担身份。
11. **数量完整性**：若主张或文案明确有 N 个步骤、层级、类别或状态，构图必须提供 N 个可辨识位置；遗漏、合并或凭空增加均标记 `FAIL`。
12. **禁区**：明确禁止可能造成误读的假截图、假数据、假背书、假流程、受保护肖像复制或多余文字。

## 整套检查

1. 只使用一个已选 Style；用户要求混用时，必须在生成前选择一种，或拆成两套并分别建立 Suite Lock。
2. 画幅、建议画布、语言与统一视觉系统完全一致；所有比例、方向和像素值无冲突。逐图比对背景基底及选择依据、颜色角色、材质纹理、线条笔触、光影、字体性格，以及适用的插画对象、人物或纸张/网点连续性；遗漏、改名导致歧义、背景色族漂移、颜色换义或媒介变化均标记 `FAIL`。
3. 有明确命名来源时，首图明确建立名称、可验证实体类型与主题；每张内页保留最小来源标识，整套至少结合两种身份表达方式。重复相同来源文字可以承担出版署名职责，但只重复同一页脚、Logo、书本或中心物体而没有其他身份机制，标记 `FAIL`。
4. 社交媒体套图提炼 4–6 个高价值信息点；教程/报告覆盖全部主要章节。
5. 相邻图片不重复同一标题位置、中心物体、页脚标签、围合深度和密度；多数图片重复“顶部标题 + 中间主体 + 底部横条”标记 `FAIL`。
6. 半调套图复用视觉词汇而非完成拼贴；交换相邻主构图后若仍同样易懂，标记 `FAIL`。
7. 所有图的认知目标互补，不是重复改写同一句话。
8. 中性比较的两侧保持视觉权重中立；不得用饱和度、明暗、尺寸或材质精致度暗示来源没有给出的优劣。

## QA 输出

```markdown
## Figure Spec QA

| 图号 | 结果 | 问题 | 修正 |
| --- | --- | --- | --- |
| 图 1 | PASS / WARN / FAIL | [证据] | [动作] |

**整套结果**：PASS / FAIL
**必须修正**：[没有则写“无”]
**复检证据**：[修正后的字段或关系，能够定位到具体图]
```

只把 QA 作为内部检查记录。完成修正后仅向用户交付三份正式产物。
