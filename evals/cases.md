# Folio v0.2 前向案例

在新的临时 Git 仓库中安装完整本地 Skill。每个案例使用独立的 `codex exec --ephemeral --skip-git-repo-check --sandbox read-only` 会话；Agent 可按 `SKILL.md` 条件读取完整 references。只提供对应案例的用户请求，不提供预期答案正文、Skill 名称或验收断言。结果记录在本次验收报告中，不把易过期的 PASS 快照提交进 Skill。

## 1. 完整内容套件

**用户请求**：

> 把下面短文写成公众号文章，并给我 4 张配图规格：某团队把每周的客服问题按主题归类。第一周有 18 个问题，第二周有 12 个；他们发现“登录失败”在两周都出现。团队决定先为登录流程补充帮助页，而不是宣称问题已经解决。

**期望触发**：触发 Folio，默认交付三产物。

**断言**：有 `publish-info`、`article-draft`、`figure-spec`；每张图的事实性文字都能在文章中逐字或等义定位。`publish-info` 有 2–3 个可复用的平台分类标签，且至少一个标签表达客服、服务运营、流程改进或语义相近的领域分类；标签不得包含 `18`、`12`、`登录失败` 或完整标题短语。

**失败条件**：缺少任一产物，或图中出现文章没有的数字、因果、结果或主张。

**Style 回归检查**：若选择半调拼贴，Style 字段使用 `Halftone Paper Collage`；中文完整生图指令使用“半调网点与纸张拼贴”等自然中文描述，不把 `Halftone Paper Collage` 当作风格前缀，也不出现 `System v2` 或其他内部 Profile 版本。

## 2. 项目采用决策

**用户请求**：

> 用 https://github.com/RealKai42/qwerty-learner 写一套项目推荐文章和 4 张配图规格，帮助开发者判断是否采用。

**期望触发**：触发 Folio；项目或工具内容一次生成采用决策型三产物。

**断言**：文章直接包含来源支持的 walkthrough、前置条件、限制、best-fit 与 not-fit；证据与编辑判断可区分；`publish-info` 和 `figure-spec` 与文章同步。`publish-info` 有 2–3 个平台分类标签，且不得包含 `Qwerty Learner`、`英文输入训练` 或 `输错后重新输入` 等具体机制短语；`工具推荐`、`开源项目`、`开发者必看` 可以出现，但不是固定答案。

**失败条件**：先交基础版再要求升级，出现升级询问，或把 README 功能列表当成推荐文章。

## 3. 数字与公式保真

**用户请求**：

> 为下面内容制作一篇文章和 4 张配图规格：温度从 20 °C 升到 35 °C，变化量是 15 °C。面积公式为 A = πr²，半径 r 的范围是 2–4 cm。不要把单位或公式改写。

**期望触发**：触发 Folio。

**断言**：文章与每张图中出现的数字、单位、范围和 `A = πr²` 完全一致。标签不得包含 `20 °C`、`35 °C`、`15 °C`、`A = πr²` 或 `2–4 cm`，且至少一个标签属于数学、科学知识、知识科普或语义相近的平台分类。

**失败条件**：改变数字或单位，或以未声明的等价形式改写公式。

## 5. 跨工具 3:4 画布约束

**用户请求**：

> 把下面知识点制作成一篇短文和 4 张 3:4 竖版配图规格：可靠的自动化要区分输入验证、执行结果和失败恢复。

**期望触发**：触发 Folio；输出跨生图工具可交接的明确画布约束。

**断言**：文件级统一比例为 `3:4 竖版（宽:高 = 3:4）`，统一建议画布为 `1536×2048 px`；每张图重复同一画幅、建议画布和下游执行要求。每条完整生图指令以最高优先级 3:4 画布约束开头，明确禁止 2:3、4:5、1:1 和横版，并以严格 3:4 原生画布收束。下游执行要求指示支持比例或尺寸参数的工具显式设置目标值且不使用 Auto；对 prompt-only 工具不承诺覆盖其固定比例。

**失败条件**：任一处出现 `1024×1536 px`、其他冲突比例或像素；缺少首尾画布约束；只依赖 prompt；或声称所有生图工具都能保证 3:4。

## 6. 相同关系的意义载体路由

分别在两个独立会话中运行以下请求。

**请求 A**：

> 把下面知识点写成一篇短文和 4 张配图规格：第一次提交报销时，新员工先收集票据，再填写信息，最后提交审批。请让读者看到一个人如何完成这组动作。不要补充票据种类、填写字段、公司制度或审批结果。

**请求 B**：

> 把下面知识点写成一篇短文和 4 张配图规格：报销请求依次处于材料待齐、信息已填、等待审批三个状态；材料未齐时停留在材料待齐，材料齐备且信息填写完成后进入信息已填，提交请求后进入等待审批。请让读者看清状态之间的边界和转化，不补充审批结果或其他状态。

**期望触发**：两者都是顺序关系，但 A 的意义由人物行动场景承载，自动选择 `Hand-Drawn Cartoon Infographic`；B 的意义由状态边界与转化承载，自动选择 `Halftone Paper Collage`。

**断言**：两份路由理由都说明核心意义载体、关键视觉机制和 removal delta；不能只以“都是顺序关系”作为选择依据。两份输出在未指定比例时都使用 `3:4 竖版（宽:高 = 3:4）` 与 `1536×2048 px`。

**失败条件**：两份请求因信息关系相同而机械选择同一 Style；理由只写题材或信息关系；Hand-Drawn 回退到 4:3；或任一输出缺少严格 3:4 约束。

## 7. 用户 Style 指定覆盖路由

**用户请求**：

> 把下面知识点写成一篇短文和 4 张配图规格，明确使用 Hand-Drawn Cartoon Infographic：系统把请求分成必填输入、可选参数和明确排除项。不要为三类补造具体条目、效果或判断标准。

**期望触发**：内容天然适合结构驱动表达，但用户指定受支持 Style，必须直接采用手绘；不得自动改回拼贴。

**断言**：所选 Style 和每张图均为 `Hand-Drawn Cartoon Infographic`；未指定画幅时仍统一为 `3:4 竖版（宽:高 = 3:4）` 与 `1536×2048 px`。

**失败条件**：覆盖用户指定、混用 Style、输出 4:3，或在产物中暴露“场景驱动解释”等内部分类名。

## 8. 视觉 QA mutation

对任一已生成的 4 张套图规格分别注入以下变异，并重新执行 Figure Spec QA：

1. 四张图都改成“顶部标题 + 中间主体 + 底部横条”。
2. 在参考图片内容没有提供的情况下加入可读终端命令、实验 ID 或状态列表。

**失败条件**：任一变异只得到 `WARN` 或被整套 `PASS` 覆盖。

## 9. 开源教程书身份连续性

分别在两个独立会话中运行同一请求：一次不指定 Style，一次明确指定 `Hand-Drawn Cartoon Infographic`。

**用户请求**：

> 把下面事实制作成一篇短文和 5 张配图规格：《Agent 工程实践》是一部公开托管在 GitHub 的开源 AI Agent 教程书，内容讲解 LLM、上下文、工具、评估和多 Agent 协作。它以章节组织概念与工程练习。不要补充作者、Star 数、许可证名称、读者评价或实验结果。

**期望触发**：触发 Folio；Style 只改变表达机制，不改变来源名称、开源教程书身份或 AI Agent 主题。

**断言**：首图明确呈现《Agent 工程实践》、开源 AI Agent 教程书与主题；每张内页在「必要署名 / 限制」和完整生图指令中逐字包含最小来源标识“《Agent 工程实践》 · 开源 AI Agent 教程书”，且不把“未提供可核查来源”、核查日期或不确定性尾注复制成图上署名；视觉锚点明确区分至少 1 个来源身份锚点与至少 2 个内容解释锚点；整套至少结合文字署名与书页、章节、阅读或工程练习中的一种非页脚身份机制。两次运行均保持相同身份事实，但 Hand-Drawn 使用场景动作，自动路由结果使用其所选 Style 的机制。

**失败条件**：只有首图能识别来源；内页退化为普通 AI Agent 海报；只重复固定页脚或书本中心构图；把 GitHub 托管扩写成未提供的许可证、Star 数或背书；或 Style 改变来源身份。
